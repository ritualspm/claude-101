# DEMO TRANSCRIPT — Session B ("fresh per topic")

> Obviously fake. Same fictional PM ("Dana"), same day's work — but done a *different* way.
> Instead of one all-day session, Dana opened a **new task per topic** and, when a single topic ran long, used **/compact** to keep it tidy. Read it and compare the ending to Session A.

---

### Task 1 — "Q3 retention" (its own task)
**Dana:** Summarize the Q3 rider-retention deck in `growth-eu`, then draft a #growth-weekly update.
**Claude:** Summary done (week-6 churn **12%**, incentive fatigue, onboarding drop-off). Draft ready, not sent.
**Dana:** Punchier, please.
**Claude:** [rewrite — still says 12%, still accurate]
> This task only ever held retention. Nothing else crowded it out.

---

### Task 2 — "Lisbon offsite" (its own task)
**Dana:** Plan the Lisbon offsite agenda.
**Claude:** [full agenda]
> Separate task. The retention thread isn't taking up room here.

---

### Task 3 — "POS vendor comparison" (its own task, and it ran long)
**Dana:** Compare the two vendor proposals in `procurement/`.
**Claude:** [detailed comparison]
**Dana:** [lots of back-and-forth… by now the task is getting long]
**Dana:** /compact
**Claude:** *Compacted.* Kept: the two vendors, the comparison criteria, and that we're leaning toward Vendor Nimbus on price + integration. Dropped the long side-tangents.
**Dana:** Which did you recommend, and why?
**Claude:** **Vendor Nimbus** — better price and cleaner POS integration. [still accurate after compacting]
> /compact wrote a tight summary of the essentials and freed up room, so the thread stayed sharp instead of falling off the edge.

---

**What the reader should notice:** every topic stayed accurate to the end. Retention still says 12%. The vendor recommendation survived because /compact preserved the essentials before the task got overloaded. Nothing had to be re-shared, because no single task was carrying an entire day of unrelated work.
