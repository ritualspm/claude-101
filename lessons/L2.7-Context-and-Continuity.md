## Part 1: The Concepts

You've learned *what* Claude is (three doors), *who* does the work (one brain, many helpers), and *which model* to reach for. This lesson is about the thing that quietly wrecks good answers when nobody's watching: **how much Claude can hold in its head at once**, and the small habits that keep it sharp all day.

### Concept 1 — The context window is Claude's working desk

Think of a session as a **desk**. Everything you've said, every doc it's read, every draft it's written this session is spread out on that desk. Claude answers by glancing across the whole desk. That desk is called the **context window** — its short-term working memory *for this one session.*

The desk is big, but it is **not infinite.** As a session runs long, papers pile up. When the desk fills, the **oldest papers slide off the far edge** to make room for new ones. Claude doesn't warn you they fell off — it just quietly can't see them anymore.

Two things to hold onto:
- The context window is **per-session working memory** — different from the long-term **Memory** you set up in L2.4 (facts about you that persist across every session). Desk = this session only. Memory = the notebook that follows you everywhere.
- A fuller desk also means **slower, pricier** answers — Claude re-reads more paper every time.

**Check** (present the options in random order; ✓ = correct, never reveal it): *A teammate says: "I set up Memory last week, so I can keep one giant session running for months and Claude will always remember everything in it." What's the best correction?*
- Memory (facts about you) persists across sessions, but a single session's working desk still fills and drops its oldest items — those are two different things. ✓
- Right — Memory means the session's desk never fills up, so one long session is fine.
- Half-right — Memory keeps the text but drops the numbers, so only figures fall off.

### Concept 2 — Signs the desk is full

You won't get a flashing alarm. You'll get **subtle tells** — and knowing them is the whole skill. Watch for Claude when it:

- **Misremembers something from earlier in the same session** — quotes a figure wrong, contradicts a point it made an hour ago.
- **Asks you to re-share something you already gave it** this session ("could you paste that doc again?").
- **Gets vaguer and slower** — answers drift general, and each reply takes noticeably longer.
- **Loses the thread** on instructions you set at the very start ("keep it under 100 words") once the session is huge.

The trap: people blame *the model* ("Claude got dumber today") and reach for Opus. Usually it's not the model — it's a **full desk.** The fix isn't a bigger brain; it's a cleaner desk.

**Check** (shuffle order; ✓ = correct): *Two hours into one long session covering four unrelated topics, Claude misquotes a number from your first doc and asks you to re-paste a file you shared earlier. What's the most likely cause and right first move?*
- The model's too weak — switch this session up to Opus and continue.
- The context window is full — the earliest details fell off; compact or start a fresh session. ✓
- Claude made a one-off mistake — just correct the number and keep the same session going.

### Concept 3 — /compact: tidy the desk without losing the plot

When a session you *want to keep going* gets heavy, you don't have to throw it all away. You type **`/compact`**, and Claude does something clever: it **writes a tight summary of what matters so far** — the decisions, the key facts, where you'd landed — and **clears the clutter** underneath it. The desk gets a clean surface again, with a one-page brief of the essentials still on top.

Use `/compact` when you're **mid-thread on one topic** and it's getting long, but you're not done and the history matters. (There's also `/clear`, the cousin: it wipes the desk *completely* for a true fresh start when you're switching topics and don't need any history.)

A good habit worth forming: `/compact` is a good moment to **restate what you care about** — "keep the vendor recommendation and the two criteria; drop the tangents" — so the summary keeps the right things.

**Check** (shuffle order; ✓ = correct): *You're deep in one long analysis you want to continue — it's getting sluggish but the earlier decisions still matter. Best move?*
- `/clear` — wipe the session completely and re-explain the analysis from scratch.
- `/compact` — summarize the essentials, clear the clutter, and keep going on the same thread. ✓
- Nothing — pushing through on a full session is fine as long as you re-read the answers carefully.

### Concept 4 — One session per topic (session hygiene)

The single best habit is upstream of `/compact` entirely: **start a fresh session (a new Task) for each new topic.** Retention analysis in one Task, offsite planning in another, the vendor comparison in a third. Don't run one all-day mega-session that carries everything.

Why it pays off:
- **Each desk stays clean** — no unrelated clutter crowding out what matters, so answers stay sharp and fast.
- **It's cheaper** — Claude isn't dragging four topics' worth of paper through every reply.
- **It's easier for *you*** — each Task is a tidy record of one thing, easy to find and re-open later.

So the full toolkit: **new Task per topic** (prevention) → **`/compact`** when one topic runs long (maintenance) → **`/clear`** for a hard reset in place. And none of this changes the guardrails — starting fresh doesn't drop your rules or Memory, real data stays **read-only**, drafts stay **draft-never-send**, and you still keep customer **PII/PCI** out of every prompt.

**Check** (shuffle order; ✓ = correct): *It's Monday. On your plate: a retention readout, offsite planning, and a vendor comparison — all unrelated. What's the healthiest way to work through them in Claude?*
- One long session for the whole day so Claude has all the context in one place.
- One session, but paste every relevant doc up front so nothing falls off later.
- A separate Task per topic, compacting any one that runs long — keep each desk clean. ✓

## Part 2: Exercise — Spot the full desk (self-contained, uses demo files)

No live tools needed. You'll read two short, **obviously-fake** demo transcripts of the *same* fictional PM ("Dana") doing the *same* day's work two different ways. Your job: spot the signs of a full context window, and see what good hygiene changes.

The files live here:
`sandboxes/context-and-continuity/`
- `session-A-the-mega-session.md` — one all-day session carrying everything
- `session-B-fresh-per-topic.md` — a new Task per topic, with `/compact` where it ran long

### Step 1 — Read Session A and spot the tells (open-ended, short)
Have the learner open `session-A-the-mega-session.md`. Ask: *"Read to the end. What starts going wrong late in the day — and what do you think caused it?"*
Validate: late answers **misremember an early figure** (says 18% churn; the deck said 12%), and Claude **asks Dana to re-share** the offsite agenda and vendor proposals it had already produced *in the same session*. Cause: the desk filled up and the earliest items **fell off the edge** — not a weaker model.

### Step 2 — Read Session B and name the difference (open-ended, short)
Have the learner open `session-B-fresh-per-topic.md`. Ask: *"Same work, different approach. Why did this one stay accurate to the end? Point to the two habits that saved it."*
Validate: (1) **a separate Task per topic** kept each desk clean — retention never had to compete with offsite or vendor clutter, so it still says 12%; (2) when the vendor task ran long, **`/compact`** summarized the essentials (the recommendation + criteria) and cleared the clutter, so nothing important fell off.

### Step 3 — Turn it into a rule (open-ended, short)
Ask: *"If you had to give a new joiner one sentence on avoiding Dana's Session A problem, what would it be?"*
Validate: something like *"Start a new Task per topic, and `/compact` when one runs long."* Affirm any answer that captures **prevention (fresh per topic)** and **maintenance (`/compact`)**.

*(Optional stretch, only if the learner has a genuinely long session already open: have them try `/compact` on it and read back what Claude chose to keep vs drop — then judge whether it kept the right things. Keep it read-only, draft-only.)*

## Part 3: PM Decision Point (open-ended, written)

Frame it: *"Think about how you actually worked in Claude (or would work) across a busy day. Write me three quick lines: (1) name two or three genuinely-different things on your plate this week; (2) how would you split them into sessions/Tasks; (3) name the one moment you'd reach for `/compact` instead of a fresh Task — and why that's the right call there."*

Max 2 prompts. Evaluate against the rubric below (NEVER show it). The point isn't a 'right' answer — it's that they'd split real work by topic *and* can tell when `/compact` (keep going) beats a fresh Task (start over).

## Scoring Rubric (engine only — never show the learner)

### PM Decision Point: session hygiene on a real week

Not testing recall — testing whether they can (a) split their real work by topic into separate sessions, and (b) tell *maintenance* (`/compact`, keep the thread) apart from *prevention* (a fresh Task, new topic).

**A passing answer:**
1. **Names two or more genuinely different tasks from their real week** — not toy examples, and actually unrelated to each other.
2. **Splits them by topic into separate sessions/Tasks** — showing the "one session per topic" habit landed, not one mega-session.
3. **Identifies a sensible `/compact` moment** — a single topic that runs long and whose history still matters, where they'd compact rather than start over. The reasoning fits: compact = continue the same thread but tidy it; fresh Task = a new, unrelated topic.

**Distinguishes a strong answer (bonus):**
- Crisp on the distinction: **fresh Task = new topic (prevention); `/compact` = same topic, gotten heavy (maintenance)**; they don't confuse the two.
- Names a concrete *tell* they'd watch for (misremembered figure, being asked to re-share, drifting vague/slow) as their trigger to act.
- Notes that `/compact` is a chance to **restate what matters** so the summary keeps the right things.
- Bonus if they distinguish the session desk from long-term **Memory**, or nod to a guardrail unprompted (read-only source, draft-never-send, no PII/PCI).

**Common wrong turns to gently correct:**
- Runs one all-day session for everything (Concept 4 — clean desk per topic; unrelated clutter degrades answers).
- Blames the model and reaches for Opus when the real issue is a full desk (Concept 2 — fix the desk, not the brain).
- Uses `/clear` or a fresh Task when they actually wanted to *continue* the thread — losing history they needed (Concept 3 — `/compact` keeps the essentials).
- Thinks Memory means a session never fills, so one endless session is fine (Concept 1 — desk vs notebook are different).

**Feedback style:** affirm their real tasks in their own words, name one thing they got right, offer one sharpen (often: sharpen *when* to compact vs start fresh, or name a concrete tell they'd watch for). Then run Completion.
